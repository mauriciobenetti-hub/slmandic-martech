Como interpretar o delta positivo
A comparação direta mostra um custo maior de R$ 177.472/ano nas ferramentas com custo informado. Isso é esperado: o HubSpot Enterprise entrega capacidades que o ZenDesk Sales + RD Station simplesmente não tinham — BUs segregadas, pipeline multi-squad, Lead Scoring, automações integradas, Custom Objects para catálogo de cursos e o Service Hub incluso (que substituirá o ZenDesk CX em fase futura, eliminando esse custo). O investimento adicional é justificado pela consolidação de plataforma e eliminação de integrações custosas entre sistemas separados.
Rubeus — permanece como sistema de inscrição
O Rubeus é voltado para ficha de inscrição e processo seletivo, não para pipeline comercial. Permanece ativo no curto prazo. A substituição futura é pelo Sistema de Inscrição Integrado ao HubSpot + RP (setup R$ 59.850 + manutenção R$ 5.600/mês) — já contemplado na proposta de implantação, como uma fase separada.
Por que HubSpot Enterprise é mandatório?
Business Units para segregar os 4 squads · Custom Objects para o catálogo de cursos · Team Permissions para a visão 360° da diretoria sem expor dados entre BUs.

Premissa de arquitetura — Data Lake / Data Warehouse

Premissa técnica crítica · Responsabilidade: TI Mandic

Toda a stack — HubSpot, ERP/SIS, WhatsApp, ZenDesk e futuras ferramentas — deve ser plugada em uma camada centralizada de dados (Data Lake ou Data Warehouse) antes de qualquer integração ponto-a-ponto direta entre sistemas.

Sem esse hub central, cada nova ferramenta adicionada cria integrações em espaguete: N sistemas falando diretamente com N sistemas, sem rastreabilidade, sem histórico consolidado e sem flexibilidade para trocar peças no futuro.

Sem Data Lake — integração espaguete

Cada sistema chama API de todos os outros diretamente. 4 ferramentas = até 12 conexões ponto-a-ponto. Qualquer mudança de credencial, schema ou versão de API quebra múltiplas integrações simultaneamente. Sem histórico consolidado, sem observabilidade, sem dados confiáveis para analytics.

Cada sistema fala apenas com o Data Lake. 4 conexões no total, independente de quantas ferramentas existam. Troca de ferramenta = reconectar 1 ponto, não N. Histórico completo, observabilidade e base para analytics confiável.
Responsabilidades por sistema — o que vive onde
Sistema Fonte de verdade para NÃO é fonte de verdade para Fluxo de dados
ERP / SIS Acadêmico Matrícula confirmada · situação acadêmica · financeiro · notas · CPF · curso cursado Histórico de captação · engajamento de marketing · jornada de lead ERP → Data Lake → HubSpot
HubSpot CRM Jornada de captação · pipeline · engajamento · lead scoring · histórico de relacionamento Dados financeiros · notas · situação acadêmica oficial HubSpot → Data Lake → Analytics
WhatsApp / Spread.Chat Histórico de conversas · templates enviados · métricas de mensageria Dados de perfil · situação acadêmica · pipeline comercial WhatsApp → Data Lake → HubSpot
ZenDesk (CX) Tickets abertos · SLAs · histórico de atendimento ao aluno Captação · marketing · dados acadêmicos ZenDesk → Data Lake → Analytics
Data Lake / DW Visão 360° consolidada · histórico cross-sistema · base para BI e analytics Operação transacional — não é sistema de registro de vendas ou matrícula Hub central de todos os fluxos
Escopo de responsabilidade — TI Mandic
Definir e provisionar a camada de Data Lake / DW
Escolha da tecnologia (ex: BigQuery, Redshift, Databricks, Azure Synapse), provisionamento de ambiente e definição do modelo de dados consolidado. Decisão a ser tomada antes da Semana 1 do projeto CRM.
Desenvolver conectores ERP → Data Lake
Pipelines de ingestão dos dados do SIS acadêmico (matrículas, situação, financeiro) com frequência definida (tempo real ou batch). Sem isso, o HubSpot não recebe confirmações de matrícula automaticamente.
Desenvolver APIs HubSpot ↔ Data Lake
Protocolo REST fornecido pela Mkt4edu/HubSpot. TI Mandic é responsável pelo desenvolvimento, teste e manutenção. Entregar dentro do cronograma do projeto (Fase 2, Semanas 4–6).
Conectar ZenDesk e WhatsApp ao Data Lake
Garantir que histórico de atendimento (ZenDesk) e conversas (Spread.Chat) sejam ingeridos no Data Lake para correlação com a jornada do aluno no HubSpot.
Definir camada de Analytics / BI sobre o Data Lake
Ferramenta de BI (ex: Looker, Power BI, Metabase) conectada ao DW para dashboards institucionais que cruzem dados de múltiplas fontes além do que o HubSpot nativo oferece.
Critérios para escolha da tecnologia

Atenção — impacto no roadmap

A definição da arquitetura de Data Lake pela TI Mandic é pré-requisito para o kickoff. As APIs de integração desenvolvidas na Fase 2 (Semanas 4–6) devem se conectar ao Data Lake, não diretamente entre sistemas.

Se o Data Lake não estiver definido até a Semana 1, o projeto de CRM pode avançar com automações e pipelines internos ao HubSpot, mas as integrações com ERP e sistemas externos precisarão ser refeitas depois — gerando retrabalho e custo adicional.

Recomendação
TI Mandic deve apresentar uma decisão de arquitetura (tecnologia + modelo de dados) até o final da Semana 1 do projeto, participando ativamente das reuniões de especificação de requisitos (Fase 1, etapa 2).
